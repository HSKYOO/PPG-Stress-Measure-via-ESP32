# PPG 실험용 데이터 수집 앱 · ESP32 + MAX30102

같은 참가자의 **rest / stress raw PPG**를 진행자가 직접 시작·정지하고 조건별로 저장하는 Windows 앱입니다. 참가자 ID와 측정자 ID는 독립적으로 기록합니다. 확대된 실시간 맥파 그래프, BPM·PPG 기반 RMSSD 추정값, Baevsky 스트레스 지수(SI) 추정값을 표시합니다. 외부 스트레스 과제는 추후 결정하며, 수학 문제·퀴즈·점수·랭킹·스트레스 등급 자동 판정은 포함하지 않습니다.

## 실시간 대시보드

왼쪽에서 연결·참가자·조건·저장을 설정하고, 오른쪽에서 수치 카드와 카운트다운·진행률·맥파를 확인합니다. 맥파 그래프가 남은 세로 공간을 모두 사용하며 창을 늘리면 함께 확대됩니다. 저장된 파일 경로는 **저장 정보** 버튼에서 확인할 수 있습니다.

- **BPM**: 최소 8초 수집 후 최근 8초 박동 간격의 중앙값으로 계산합니다.
- **RMSSD (ms)**: 최소 30초와 20개 이상의 유효 맥파 간격이 있어야 표시합니다. 최근 최대 60초의 인접 간격 차이 제곱 평균의 제곱근입니다. ECG의 NN 간격으로 검증한 HRV가 아닌 **PPG 맥파 간격 기반 추정값**입니다.
- **스트레스 지수 (SI)**: 최소 60초의 연속 수집과 유효 맥파 간격 30개 이상이 필요합니다. 최근 60초의 맥파 간격으로 `SI = AMo(%) / (2 × Mo(s) × [최대 간격 − 최소 간격](s))`를 계산합니다. 0초를 기준으로 고정한 50ms 폭의 히스토그램에서 가장 높은 bin의 비율을 AMo, 그 bin의 중앙값을 Mo로 사용합니다. 동률이면 간격이 짧은 bin을 선택합니다. 제곱근·로그 변환이나 Kubios의 추가 detrending은 적용하지 않습니다. 명목 100Hz PPG의 수치 불안정을 줄이기 위한 앱 정책으로 간격 변동폭이 10ms 미만이면 표시하지 않습니다. rest 비교값은 필요하지 않으며 두 조건 모두 표시합니다. SI는 0~100% 확률이 아니며 ECG·심리검사와 대조해 검증한 결과나 임상 진단이 아닙니다. 정상/위험 등급은 붙이지 않습니다.
- **그래프**: 최근 10초의 IR 맥파에서 DC 성분을 제거하고 0.5~4 Hz 필터를 적용한 파형과 검출된 피크를 표시합니다. 수치는 1초마다 갱신합니다.

추정 시간축은 현재 펌웨어의 명목 100 Hz 설정과 `sample` 순번에 기반합니다. 센서 시각이 없으므로 실제 하드웨어의 샘플 누락이나 클록 오차까지 검증하지는 못합니다. 순번 단절·재시작 시 계산 창을 초기화하며 평탄·포화·불규칙 간격·잡음 검사에서 탈락하면 수치를 숨깁니다. 이 품질 검사는 연구/임상 정확도를 보장하지 않습니다. 참가자/조건 전환과 측정 시작 시 계산 창을 새로 만듭니다. 추정값은 화면 표시용이며 원본 CSV에는 기존 raw 데이터가 그대로 저장됩니다.

계산 방법과 해석의 범위는 [SPR의 심박수·HRV 측정 지침](https://onlinelibrary.wiley.com/doi/10.1111/psyp.14604)을 참고했습니다. SI 계산식과 PPG 적용 사례는 [Sensors 2023 연구](https://www.mdpi.com/1424-8220/23/12/5511), 계산 방식에 따른 차이는 [Baevsky SI 방법 연구](https://journals.physiology.org/doi/10.1152/ajpregu.00243.2024)를 참고했습니다. 이 앱은 해당 연구의 학습된 예측 모델을 구현하지 않습니다. 필터와 피크 검출은 [SciPy Signal](https://docs.scipy.org/doc/scipy/reference/signal.html)을 사용합니다. 실제 센서의 BPM·RMSSD·SI 정확도는 기준 장비와 별도로 비교해야 합니다.

## 기존 코드 확인 결과와 재사용

기준 저장소: <https://github.com/gunminy/esp32-max30102-ppg-raw>, 확인한 커밋 `10941fe57f9460cf988542846744a14d0d452127`.

- `src/main.cpp`: MAX30102의 raw Red/IR를 100 Hz 설정으로 읽고, 115200 baud에서 `sample,red,ir` 헤더와 정수 3개를 한 줄씩 출력합니다. `sample`은 출력 순번이며 보드 재시작 시 0으로 돌아갑니다. **펌웨어는 타임스탬프를 보내지 않습니다.** 정상 수집 형식과 센서 설정은 유지하며, 초기화 실패 시 I²C 진단 정보를 추가했습니다.
- 기존 `record_ppg.py`: 포트 연결 후 2초 대기하고, 유효한 정수 3개 행을 CSV에 저장합니다. `time.monotonic()`으로 종료 시간을 재고, 파일은 `x` 모드로 생성하며 100행마다 flush합니다.
- 기존 파싱 규칙·115200 baud 포트 열기를 `ppg_io.py`로 분리해 기존 CLI와 새 앱에서 함께 사용합니다. 기존 CLI 및 실행 도우미도 계속 사용할 수 있습니다. 새 앱은 UI가 멈추지 않도록 timeout=0으로 주기적으로 수신합니다.

## Windows에서 실행하기

Python **3.10 이상**(공식 Windows 설치본의 Tcl/Tk 포함), ESP32 USB 드라이버가 필요합니다. 최초 의존성 설치에는 인터넷이 필요합니다.

1. 아래 기존 배선/펌웨어 안내에 따라 ESP32에 업로드합니다. **PlatformIO Serial Monitor는 종료**해서 포트를 해제합니다.
2. 이 폴더에서 PowerShell을 열고 실행합니다.

   ```powershell
   .\start_experiment_windows.bat
   ```

   도우미는 `.venv`를 생성하고 `requirements.txt`의 pyserial을 설치합니다. 직접 설치·실행하려면:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\python.exe -m pip install -r requirements.txt
   .\.venv\Scripts\python.exe -m app.main
   ```

3. 기본 포트 **COM9**를 확인합니다. 다른 포트는 드롭다운에서 선택하거나 직접 입력합니다. USB 연결 후에는 **포트 새로고침**을 누릅니다.
4. **센서 연결**을 누르고 약 2초 뒤 `유효 데이터 수신` 및 sample/Red/IR 값이 표시되는지 확인합니다. 이 표시는 데이터 통신 확인이며 손가락 접촉이나 신호 품질 판정은 아닙니다.
5. **참가자 ID**, **측정자 ID**, `rest` 또는 `stress`를 입력·선택합니다. 필요하면 구간 길이(초), 구간 개수, 저장 폴더를 바꿉니다.
6. **측정 시작 (Space)** 버튼을 누릅니다. 기본은 **60초 × 3구간 = 180초 연속 기록**이며 구간 사이에 멈추지 않습니다. 1분 단위 CSV 3개로 나누어 저장합니다. 화면에 참가자, 조건, 구간, 구간/전체 남은 시간, 수신 상태, 저장 샘플 수가 표시됩니다.
7. **참가자마다 스트레스 과제 전 `rest`를 먼저 3분 측정**합니다. 전체 종료 후에는 자동으로 다음 측정을 시작하지 않고 대기합니다. 같은 참가자 ID로 조건을 `stress`로 바꾸고 외부 과제 시작에 맞춰 시작 버튼 또는 **Space**를 누릅니다. stress 종료 후 다음 참가자로 교체하고 ID와 `rest` 조건을 설정한 뒤 다시 시작합니다. 교체·준비 중 수신 데이터는 저장하지 않으며 새 측정마다 타이머가 0부터 시작합니다.
8. 측정 중에는 ID·조건·설정을 고정합니다. **측정 중도 정지**를 누르면 받은 데이터까지 보존합니다. Space는 측정 중에는 정지 기능이 없고, 길게 눌러도 중복 시작하지 않습니다. ID나 경로 등 입력란에 포커스가 있으면 Space는 문자 입력으로 동작하므로 시작 버튼을 누르거나 Tab으로 버튼으로 이동한 후 사용하세요.

실물 센서 없이 같은 화면과 수집·저장 경로를 실행하려면:

```powershell
.\start_experiment_windows.bat --simulate
```

모의 모드에서도 **센서 연결 → ID 입력 → 조건 선택 → 측정 시작** 순서입니다. 짧게 확인할 때 구간 길이를 `2`, 개수를 `3`으로 설정하세요. 제목에 `모의 입력`, JSON에 `source: simulation`이 표시됩니다. **연결 해제**로 측정 중 연결 중단도 확인할 수 있습니다. 모의 데이터는 실험 자료와 구분해서 보관하세요.

## 저장 형식과 시간 기준

기본 저장 폴더는 이 저장소의 `data/`입니다. 앱은 조건 측정마다 UTC 시작 날짜·시간(마이크로초) + UUID로 세션을 만들고, 기본 설정에서 `<session_id>_segment01.csv`, `_segment02.csv`, `_segment03.csv`와 `<session_id>.json`을 생성합니다. CSV 3개는 같은 참가자·조건·세션 ID를 공유하며 JSON의 `csv_files`와 `segment_samples`에 파일 목록과 구간별 샘플 수를 기록합니다. 중도 정지하면 아직 측정하지 않은 구간 파일은 헤더만 있고, JSON은 `interrupted` 상태입니다. ID를 파일 경로로 사용하지 않고 CSV는 배타적 생성(`x`)으로 열기 때문에 재측정해도 덮어쓰지 않습니다. 기존 CLI의 단일 CSV 형식은 유지합니다.

CSV 열:

| 열 | 의미 |
| --- | --- |
| `session_id` | 이번 한 번의 조건 측정 식별자. rest/stress 재측정마다 새 값 |
| `participant_id`, `operator_id` | 참가자와 측정자 ID. 두 조건 비교 시 참가자 ID로 연결 |
| `condition` | `rest` 또는 `stress` |
| `segment` | 실제 경과 시간으로 정한 1부터 시작하는 구간 번호 |
| `received_at_utc` | PC가 시리얼 바이트 묶음을 읽은 UTC 시각(ISO 8601). 같은 묶음의 여러 샘플은 같은 시각일 수 있음 |
| `elapsed_seconds` | 측정 시작 이후 PC 단조 증가 시계 기준 경과 초 |
| `sample`, `red`, `ir` | ESP32가 전송한 원본 순번과 raw ADC 값. 필터링·정규화하지 않음 |

구간은 `[0, 60)`, `[60, 120)`, `[120, 180)`초입니다. 정확히 60초인 샘플은 2구간 파일, 120초는 3구간 파일에 기록하며 180초 이후 수신분은 저장하지 않습니다. 파일 경계에서 센서나 타이머를 재시작하지 않고 `elapsed_seconds`도 0~180초의 연속 시간으로 보존합니다. 샘플 개수나 `sample/100`으로 구간을 추정하지 않습니다. 누락·중복·순번 초기화가 있더라도 시간 기준 구간은 유지됩니다.

측정 시작 시 대기 중 쌓인 입력 버퍼를 비우고, 실물 시리얼에서는 첫 줄 경계를 지나 수집합니다. 따라서 첫 샘플은 버튼 시점보다 약간 늦을 수 있습니다. PC 수신 시각은 센서 측정 시각이 아니며, USB·시리얼·센서 FIFO 지연과 UI 폴링(약 20 ms)이 포함됩니다. 현재 펌웨어에는 센서 타임스탬프가 없으므로 이를 만들어서 센서 시각으로 표시하지 않습니다. 다른 장비와 정밀하게 동기화하려면 펌웨어 타임스탬프와 동기화 설계가 추가로 필요합니다.

### 완료·중단 기록

세션 JSON을 해당 구간 CSV들과 함께 보관하세요. JSON은 ID·조건·구간 설정·입력 출처·시작/종료 UTC·실제 경과 시간·전체 및 구간별 저장 샘플 수·파일 목록 및 다음 상태를 기록합니다.

| `status` | 의미 |
| --- | --- |
| `recording` | 기록 중. 앱 강제 종료·PC 전원 차단 후에도 이 값이면 정상 종료가 확인되지 않은 세션 |
| `completed` | 설정한 전체 시간이 경과하여 정상 완료 (`duration_elapsed`) |
| `interrupted` | 중도 정지(`operator_stop`), 연결 해제(`operator_disconnect`), 창 닫기(`window_closed`), 입출력 오류(`io_error: ...`), 유효 샘플 5초 미수신(`data_timeout_5s`), 기록 구간에 샘플 없음(`no_samples_received`) |

수신 예외와 `# ERROR` 센서 오류는 중단 처리합니다. 케이블 분리 시 OS 예외가 없더라도 유효 데이터가 5초 동안 없으면 연결을 닫고 중단합니다. 포트만 열리고 데이터가 없는 상태에서는 측정을 시작할 수 없습니다. 재연결은 진행자가 포트를 확인하고 **센서 연결**을 눌러 수행합니다.

중도 정지·연결 오류·창 닫기는 CSV를 flush/close하고 JSON을 최종 상태로 갱신합니다. 수집 중에도 약 1초마다 flush합니다. 강제 프로세스 종료·정전·디스크 고장의 경우 최근 미반영 데이터와 최종 상태 갱신은 보장할 수 없습니다. 저장 오류 시 화면의 경로에서 기존 CSV와 JSON을 확인하세요. JSON의 종료 상태가 없으면 정상 완료로 취급하지 마세요.

실제 장비에서는 다음을 확인해야 합니다.

- COM9(또는 실제 포트) 선택, USB 드라이버, 포트 점유 해제, ESP32 재시작 후 유효 Red/IR 수신
- 손가락 접촉과 움직임에 따른 raw 파형, 센서 포화 여부, 실제 수신률과 `sample` 연속성
- 기본 180초 동안 구간 1/2/3과 조건·두 ID가 맞게 저장되고 종료 JSON이 `completed`인지 확인
- 측정 중 케이블 분리 시 즉시 또는 최대 약 5초 후 `interrupted`가 되고 기존 CSV가 읽히는지 확인
- rest/stress 반복 및 측정자 변경 시 이전 파일 보존, 외부 과제와 진행자 시작 시점 일치

### 센서 초기화 실패 진단

`MAX30102 not found`만으로 배선 불량이나 센서 고장을 확정할 수 없습니다. 라이브러리는 I²C 주소 `0x57`에서 Part ID `0x15`를 읽어야 초기화에 성공합니다. 최신 `src/main.cpp`는 초기화 실패 시 `# RETRY:` 진단을 출력하고, I²C 버스를 종료한 뒤 2초 대기하여 버스 생성과 센서 초기화를 다시 시도합니다. 진단도 매번 새로 수행합니다. 성공하면 자동으로 정상 수집을 시작하며 CSV 형식은 동일합니다.

앱은 초기화 재시도 메시지가 오는 동안 연결을 유지하고 `센서 초기화 재시도 중`을 표시합니다. 유효 샘플이 오기 전에는 측정을 시작할 수 없습니다. 재시도 메시지마저 5초간 끊기면 연결을 해제하며, 이미 데이터를 수신하거나 측정 중인 상태에서 재시도 메시지가 오면 중단 처리합니다. 기존 `# ERROR` 메시지는 계속 즉시 오류로 처리하므로 **앱을 다시 실행하고 새 펌웨어도 업로드**해야 변경 동작을 사용할 수 있습니다.

- `I2C devices=none; ... no ACK at 0x57`: 현재 핀에서 응답 장치 없음. 전원/핀 배치/모듈 동작을 구분해서 확인해야 하며 이것만으로 고장 확정 불가
- `I2C devices=0x57; ... PART_ID=...`: 주소 응답은 있음. `0x15`와 다른 값이면 모듈 종류 또는 레지스터 통신을 확인
- `PART_ID read failed`: 주소 ACK 이후 레지스터 읽기 실패
- `PART_ID=0x15`인데 초기화 실패: 처음 초기화 때와 진단 시점의 결과가 달라 일시적 통신/기동 상태 등을 추가 확인

추가 진단의 `probe_0x57`은 `Wire.endTransmission()` 반환값입니다. 설치된 ESP32 Wire 구현에서 `0`은 성공, `2`는 NACK/장치 미발견, `5`는 타임아웃입니다. `I2C controller released` 행은 버스를 종료하고 SDA/SCL을 내부 풀업 입력으로 바꾼 뒤 읽은 값으로, 스캔 직후의 레벨과 구분해서 확인합니다. 이 값만으로 센서 고장이나 배선 불량을 확정하지 않습니다.

진단 펌웨어의 빌드/업로드 명령은 `pio run -e esp32dev`, `pio run -e esp32dev -t upload --upload-port COM9`입니다. 업로드 전 앱과 Serial Monitor에서 포트를 해제하세요. 모듈의 허용 전원을 확인하지 않고 VIN을 5V로 바꾸지 마세요.

## 앱 추가·변경 파일

`app/main.py`(진행자 UI, 실물/모의 수신), `app/recording.py`(시간 구간·CSV·상태), `ppg_io.py`(기존 CLI와 공유하는 전송 형식), `record_ppg.py`(공유 함수 재사용), `start_experiment_windows.bat`, `requirements.txt`, `tests/`, `.gitignore`, 이 README입니다. `app/math_task.py`는 만들지 않습니다.

# 기존 CLI · 배선 및 펌웨어 안내

아래 수집 명령·CSV·타임스탬프 설명은 기존 `record_ppg.py` CLI에 대한 안내입니다. 실험 앱의 확장 CSV와 시간 기준은 위의 앱 안내를 따르세요.

지능형신호처리 실습수업에서 사용할 **PPG 원시 데이터를 수집하고 CSV로 저장**하기 위한 저장소입니다. ESP32와 MAX30102로 적색(Red)·적외선(IR) 두 채널의 데이터를 수집합니다.

Windows와 macOS에서 같은 펌웨어와 Python 수집 프로그램을 사용합니다.

**수집 흐름:** 센서 연결 → 펌웨어 업로드 → CSV 저장

## 1. 준비물과 연결

- ESP32 개발 보드, MAX30102 센서 모듈, 점퍼선
- USB **데이터** 케이블
- [VS Code](https://code.visualstudio.com/)와 **PlatformIO IDE** 확장
- [Python 3](https://www.python.org/downloads/): Windows는 `py`, macOS는 `python3` 명령을 사용할 수 있도록 설치

**USB 전원을 분리한 상태에서** 다음과 같이 연결합니다.

| MAX30102 모듈 | ESP32 |
| --- | --- |
| VIN | 3V3 |
| GND | GND |
| SDA | GPIO21 |
| SCL | GPIO22 |

모듈의 핀 표기를 먼저 확인하세요. 이 실습에서는 **VIN을 3V3에 연결**합니다. 배선을 마친 뒤 ESP32를 USB 데이터 케이블로 컴퓨터에 연결합니다.

## 2. 펌웨어 업로드

1. VS Code의 `File > Open Folder`에서 이 저장소 폴더 전체를 엽니다.
2. ESP32를 USB로 연결합니다.
3. PlatformIO의 **Upload (→)**를 눌러 펌웨어를 업로드합니다.
4. **Serial Monitor**를 열어 `sample,red,ir` 형식의 숫자가 나오는지 확인합니다. 통신 속도는 **115200 baud**입니다.
5. 확인이 끝나면 **Serial Monitor를 종료**합니다. 모니터 터미널을 종료해 포트를 해제하세요.

> **CSV 수집 중에는 Serial Monitor를 켜두지 마세요.** 두 프로그램이 같은 시리얼 포트를 동시에 사용할 수 없습니다.

보드 설정은 [platformio.ini](platformio.ini)의 `esp32dev`입니다. 다른 ESP32 보드를 사용한다면 해당 보드에 맞게 설정을 확인합니다.

## 3. CSV로 데이터 저장

VS Code에서 `Terminal > New Terminal`을 열고, 현재 위치가 이 저장소 폴더인지 확인합니다. 첫 실행 시 실행 도우미가 `.venv`를 만들고 `pyserial`을 설치하므로 인터넷 연결이 필요합니다.

### Windows · PowerShell / cmd

연결된 포트를 확인합니다.

```powershell
.\start_windows.bat list
```

목록에서 ESP32에 해당하는 **USB 시리얼 포트**를 찾습니다. `CP210x`, `CH340` 등 USB-UART 장치 설명을 참고하고, Bluetooth 포트와 구분하세요.

아래는 **COM12가 ESP32 포트인 경우**의 예시입니다. 각자 조회한 포트 이름으로 바꿔 실행합니다.

```powershell
.\start_windows.bat COM12 30
```

### macOS · Terminal

연결된 포트를 확인합니다.

```bash
bash start_macos.sh list
```

목록에 나온 실제 포트 이름으로 실행합니다. 아래 이름은 예시입니다.

```bash
bash start_macos.sh /dev/cu.usbserial-110 30
```

포트 이름은 보드에 따라 `/dev/cu.usbserial-*`, `/dev/cu.wchusbserial*`, `/dev/cu.SLAB_USBtoUART` 등으로 표시될 수 있습니다.

### 측정과 저장 결과

1. 손가락을 센서의 측정면에 가볍게 올려 고정합니다.
2. 수집 명령을 실행하고, 측정 중 손가락과 센서가 움직이지 않도록 합니다.
3. 터미널의 `100 samples saved`와 같은 메시지로 저장 진행을 확인합니다.
4. 종료 후 이 저장소 폴더에 생성된 **`ppg_raw_날짜_시간.csv`**를 확인합니다.

마지막 인수 `30`은 초 단위의 수집 시간입니다. 시간 제한 없이 기록하려면 `30`을 생략하고, **`Ctrl+C`**로 종료합니다.

현재 프로그램은 포트 연결 후 2초간 기다린 다음 수집 시간을 잽니다. 이때 대기 중 버퍼에 쌓인 데이터도 저장될 수 있으므로, **30초 실행이 정확히 3,000개 샘플을 의미하지는 않습니다.**

## 4. 데이터 형식과 측정 설정

CSV의 첫 행은 열 이름이며, 이후 각 행에는 Red와 IR 한 쌍이 저장됩니다. 다음은 형식 예시입니다.

```csv
sample,red,ir
0,85432,76215
1,85521,76302
2,85689,76488
```

| 열 | 의미 |
| --- | --- |
| `sample` | ESP32가 읽어서 출력할 때 붙이는 순번. 보드가 재시작되면 0부터 시작 |
| `red` | 적색 LED로 측정한 원시 ADC 값 |
| `ir` | 적외선 LED로 측정한 원시 ADC 값 |

`red`와 `ir`는 ADC 카운트이며, 심박수나 산소포화도 값이 아닙니다.

| 설정 | 현재 값 |
| --- | --- |
| 채널 | Red + IR |
| 샘플링 주파수 | **100 Hz** · 채널당 초당 100개로 설정 |
| FIFO 평균화 | 1 · 평균화하지 않음 |
| LED 펄스 폭 / ADC 해상도 | 411 µs / 18 bit |
| ADC 범위 | 4096 nA |
| 시리얼 통신 | 115200 baud |

설정은 [src/main.cpp](src/main.cpp)의 `sensor.setup(0x1F, 1, 2, 100, 411, 4096)`에서 확인할 수 있습니다. 소프트웨어 필터링, 심박수 및 SpO₂ 계산은 수행하지 않습니다.

### 타임스탬프와 시간축

현재 CSV에는 개별 샘플의 측정 시각이 없습니다. **100 Hz로 누락 없이 수집됐다고 가정**하면, 첫 번째 저장 샘플을 기준으로 상대 시간을 계산할 수 있습니다.

```text
시간 [초] = (현재 sample - 첫 번째 저장 sample) / 100
```

위 가정에서 샘플 번호 차이가 1이면 0.01초, 100이면 1초에 해당합니다. 이는 설정된 샘플링 주파수를 기준으로 계산한 상대 시간입니다.

- 파일 이름의 날짜·시간은 PC에서 수집을 시작할 때 만든 값이며, 각 샘플의 측정 시각이 아닙니다.
- `sample`의 연속성으로 전송 도중 빠진 행이나 보드 재시작을 확인할 수 있습니다. 단, **센서 FIFO나 라이브러리 내부에서 발생한 누락까지 확인할 수는 없습니다.**
- PC가 데이터를 받은 시각은 센서의 측정 시각과 다릅니다. 다른 장비와의 정밀한 시간 동기화에는 추가적인 수집 설계가 필요합니다.

## 5. 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| 포트 목록에 ESP32가 없음 | USB 데이터 케이블인지 확인하고, 보드의 USB-UART 칩에 맞는 드라이버 확인 |
| `Access denied` 또는 포트 열기 실패 | Serial Monitor와 같은 포트를 사용하는 프로그램을 종료하고, 포트 이름 재확인 |
| 업로드 실패 | 포트 점유 여부와 보드 설정 확인. 일부 보드는 업로드 연결 시 `BOOT` 버튼 조작 필요 |
| `MAX30102 not found` | 전원을 분리한 뒤 VIN–3V3, 공통 GND, SDA–GPIO21, SCL–GPIO22 배선 확인 |
| CSV에 `sample,red,ir`만 있음 | 실제 ESP32 포트인지 확인. 수집을 종료한 뒤 Serial Monitor에서 센서 오류 확인 |
| `py` / `python3` 명령을 찾을 수 없음 | Python 설치와 명령 실행 가능 여부를 확인한 뒤 터미널 다시 열기 |
